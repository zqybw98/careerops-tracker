A local-first Streamlit application for managing job applications, importing structured application notes, and turning recruiting emails into explainable workflow updates.

## 30-second summary

CareerOps Tracker opens directly on an applications-first workspace. The master list, search, filters, quick add, and record editing are the primary workflow; analytics and lower-frequency tools remain available without crowding the default screen.

The project demonstrates:

- Python workflow automation and Streamlit product UI
- SQLite persistence with versioned migrations
- Explainable, rule-based recruiting-email classification
- Safe local parsing of structured ChatGPT output
- pytest, coverage, ruff, mypy, pre-commit, and GitHub Actions

## Core Workflow

### Applications-first workspace

- `Applications` is the default page, with the application list visible immediately.
- Top-level navigation is limited to `Applications`, `Analytics`, and `More`.
- Search covers company and role; filters cover location and status.
- Quick filters provide focused `All`, `Active`, `Interview`, `Waiting`, and `Rejected` views.
- `+ Add Application` opens a compact dialog for fast manual entry.
- Selecting a row opens its details for status, location, dates, next action, source, contact, notes, and rejection-reason editing.
- Analytics, contacts, email workflows, data tools, bulk cleanup, and company research remain available through `Analytics` or `More`.

### Direct application import

The advanced application intake accepts:

- raw JSON generated by ChatGPT;
- fenced `json` code blocks;
- Markdown or plain-text key-value notes such as `Company: SAP` and `Position: QA Engineer`.

After parsing, the application can be created directly or extracted into the full form for review. Company and role are required. Statuses and dates are normalized, supported fields are cleaned before saving, and unknown fields are ignored. Likely duplicates are shown for review instead of being created silently.

This importer is a local text parser. It does not call OpenAI or send application data to an external AI service.

### Company and location suggestions

- Company suggestions come from existing application records.
- Location suggestions combine common Germany locations with locations already stored in the database.
- New companies and custom locations remain valid inputs.
- Existing values are preserved when an application is edited.

Suggestions are local conveniences, not network autocomplete, Google Places results, an external company database, or a live job-board query.

### Company research notes

Company Explorer can search prior companies and roles and store dated career-page checks, relevant roles, skipped roles, decisions, notes, and source links. These records stay in local SQLite. Migration `006_add_company_research_notes.sql` creates the `company_research_notes` table and lookup indexes.

The optional private-data export includes approved company research fields when the table is present. Company Explorer records user-entered research; it does not perform automatic internet research.

## Other Features

- Classify English, German, and Chinese recruiting emails as confirmation, recruiter reply, interview, assessment, rejection, follow-up, or other.
- Extract company, role, location, contact, source link, deadlines, interview dates, and rejection reasons from pasted emails.
- Match emails to existing applications, show confidence and evidence, and let the user adjust fields before applying an update.
- Gate status updates by confidence and retain manual correction feedback for similar future messages.
- Draft Saved applications from pasted job descriptions or job URLs.
- Generate follow-up, interview thank-you, recruiter outreach, and rejection acknowledgement templates.
- Provide contact-centric CRM views, reminder workflows, calendar `.ics` export, CSV import previews, backups, and decision analytics.
- Keep optional Gmail synchronization local, read-only, and review-first.

## Privacy and Data Safety

- Core application data is stored locally in SQLite.
- Structured application import runs locally and does not transmit text to an AI API.
- Gmail sync is optional, local-only, and uses read-only OAuth.
- Local OAuth credentials and tokens are ignored by Git.
- Private export tooling uses an approved field list rather than copying arbitrary database columns.
- Sample data is synthetic and suitable for the public demo.
- Do not paste sensitive real application data into a public hosted demo.

## Known Limitations

- Email and job-post analysis is rule-based and can miss unusual messages or layouts.
- Company and location suggestions are based on local history and a small built-in location list; they are not externally verified.
- Gmail sync is local-only and unavailable in the hosted demo.
- The app is designed for an individual workflow, not a multi-user team.
- Calendar integration is export-based via `.ics`, not two-way calendar synchronization.


Set `CAREEROPS_DB_PATH` before launch to use a separate database for demos, screenshots, or experiments.

## Daily Workflow

1. Open `Applications`; the searchable master list appears first.
2. Use company/role search, location/status filters, or a quick filter to find the relevant record.
3. Add a record with `+ Add Application`, or select an existing row to edit it.
4. For ChatGPT-generated JSON or structured notes, use `More > Advanced applications` and choose direct import or form review.
5. For recruiting messages, use `More > Email tools`, review the match and suggested update, then apply only the confirmed fields.
6. Use `Analytics` when you need pipeline or decision analysis rather than routine record maintenance.

## Data, Import, and Migrations

- Application data, activity events, email feedback, and company research notes are stored in SQLite.
- `schema_version` records applied migrations; migration 006 adds company research notes and indexes.
- CSV import previews created, updated, and unchanged rows before writing.
- Re-importing the same company, role, and application date updates the existing record instead of creating an exact duplicate.
- Data tools provide application CSV, activity-log CSV, SQLite backup, and calendar exports.
- Optional private export produces approved CSV and SQL snapshots and includes company research notes when available.

## Testing and Coverage

Install development dependencies:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

Run the complete checks:

```powershell
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m ruff format --check .
.\.venv\Scripts\python.exe -m mypy src
.\.venv\Scripts\python.exe -m pytest
```

Run tests with coverage:

```powershell
.\.venv\Scripts\python.exe -m pytest --cov=src --cov-report=term-missing
```

Regression tests cover application-list behavior, structured note import, classification, parsing, reminders, CSV synchronization, migrations, private export, analytics, Gmail preview behavior, and workflow services.

## Optional Gmail Sync

Install the optional dependencies:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-gmail.txt
```

Create a Google OAuth desktop credential and save it locally as `credentials.json`. Then open `More > Email tools > Gmail Sync`. The first local sync opens Google's OAuth screen and stores `token.json` for later runs.

The app requests the read-only Gmail scope and previews suggestions before applying updates. `credentials.json` and `token.json` are ignored by Git.

## Configurable Rules

Most rule-based behavior lives in JSON under `config/`:

- `email_classification_rules.json`: multilingual categories, status mappings, actions, and confidence settings.
- `email_parser_rules.json`: extraction patterns, locations, intent keywords, rejection reasons, and match thresholds.
- `job_post_rules.json`: job-post extraction, job-board domains, role and deadline keywords, and Saved defaults.
- `reminder_rules.json`: priorities, waiting thresholds, messages, and due-date behavior.

Configuration loaders validate required structure and values at startup so malformed rules fail early with a clear error.

## Why This Project

CareerOps Tracker began as a compact portfolio MVP and evolved into a local-first workflow tool for structured job-search operations. Its current scope emphasizes fast application maintenance, explainable automation, traceable updates, privacy, and testable business rules rather than adding more dashboard features.

The project is relevant to QA, automation, technical operations, system integration, and internal-tooling roles.
